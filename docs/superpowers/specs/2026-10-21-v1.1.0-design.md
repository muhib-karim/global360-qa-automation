# v1.1.0 design: a green, trustworthy E2E badge

## Intent

The E2E badge on `main` is red. A hiring manager reading this portfolio sees a red badge before any code. The
nightly run of 2026-10-21 (run 39569739741) failed for two separate reasons:

1. The browser download logged `getaddrinfo ENOTFOUND` for one Playwright CDN host. Playwright fell through to
   another host that time, but nothing in the workflow protects against every host failing, and every run
   downloads about 190 MiB of browser again.
2. `Macbook_can_be_created_checked_out_found_and_audited` failed in all three browsers on the History date
   assertion: the cell read `Wed Oct 21, 2026 4:31AM` and the regex `\b\d{4}\b.*\b\d{1,2}:\d{2}\b` did not match.

## Goals

- Browser install that survives a CDN host outage: cache keyed on the Playwright version, retries with backoff,
  fallback to an alternate download host.
- A History date assertion that is correct for every date and time format Snipe-IT offers, on any runner locale
  or timezone, and that still proves the cell holds a real, current timestamp.
- Flakiness controls: failure traces uploaded as their own artifact, a documented quarantine mechanism with an
  expiry that a unit test enforces.
- The Pages site shows the latest E2E report with pass counts per browser.
- Docs: README showcase and architecture section, CHANGELOG `[1.1.0] - 2026-10-21`, HANDOFF.md, SKILLS_USED.md.

## Non-goals and anti-goals

- No weakening: replacing the regex with "any text" or a looser pattern counts as failure even if green.
- The failing test must not be quarantined, skipped or retried into green.
- No new runtime dependencies in the test project.

## Decisions (my calls, the task forbids questions)

- Date: a `SnipeItDate` parser in `Data/` with `CultureInfo.InvariantCulture` and the exact list of Snipe-IT's
  date and time display formats. The page object asserts that both History rows parse and fall inside the window
  any server timezone allows (UTC-12 to UTC+14) around the test run, and that the two rows are within two minutes
  of each other.
- Install: `.github/scripts/install-browsers.sh` with attempts, exponential backoff and a host list, used by the
  E2E workflow; `actions/cache` on `~/.cache/ms-playwright`.
- Quarantine: `[Quarantine(reason, until)]` attribute adding the `Quarantine` NUnit category; the gating run
  excludes it, a non-blocking job runs it, a unit test fails once `until` has passed.
- Pages: deploy stays on `main` (the `github-pages` environment only allows `main`); every run builds the site as
  an artifact so the branch proves the same output.
- Workflows also run on pushes to `upgrade/**` so the branch head can be verified without opening a PR.
